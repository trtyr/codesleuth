# 微观 · 向量组装（vector-compose）

> 置信度 high · 6 条发现 · 303827 tokens

向量组装链路（CLI 解析 embed_mode → build_vector_index → plan_chunks → compose_input → EmbedClient::embed → commit_build → recall/vector_search）整体设计成熟（原子事务、索引对齐校验、去重回填都有针对性修复注释），但仍发现 2 个真实缺陷与 2 个疑似缺陷：①plan_chunks 对「codegraph 符号表与工作区文件不同步（文件被清空）」的场景会在符号主块切片处直接 panic（越界）；②Composite 模式下超大符号的子窗块 text 只含面包屑不含 header（签名/docstring），导致只改签名或 docstring 时 text_hash 不变、旧向量被错误复用（增量复用投毒）；③embed_one 错误消息按字节切片 &snippet[..200]，多字节（中文）错误体恰好切在字符边界中间时 panic，把可重试错误变成 JoinError；④残留的 descriptions 表全仓库无任何写入方，是被裁决移除功能的残余物。bug 密度最高文件：src/vector/chunk.rs。最值得先修：plan_chunks 空文件越界 panic（P1）。

1. 【P1·边界越界 panic】plan_chunks 符号主块路径未做空文件防护：若 codegraph db 与工作区不同步（文件在 codegraph 索引后被清空/截断为 0 字节），read_lines 返回 Some(空 Vec)（chunk.rs:168-175 只查大小不查空），随后 start = sym.start_line.max(1).min(lines.len().max(1)) = 1，end = sym.end_line.min(0).max(1) = 1，body = lines[eff_start-1..*end] = lines[0..1] 在空 Vec 上切片 panic。触发条件：nodes 含某文件符号行 + 磁盘上该文件为空（file: 0 字节）。错误行为：进程 panic；应有行为：跳过该文件。上游防线不成立：fallback 路径有 lines.is_empty() 防护（chunk.rs:418）而符号路径没有——典型的复制粘贴漏改。（src/vector/chunk.rs:285-307、src/vector/chunk.rs:168-175、src/vector/chunk.rs:418-420）
2. 【P2·增量复用投毒】Composite 模式下超大符号的子窗块：text = 面包屑 + 子窗行（chunk.rs:322-333），而 compose_input 的 Composite 输入 = chunk.header（面包屑+签名+docstring，chunk.rs:71 注释/208-218）+ 标识符。header 变化（仅改签名或 docstring）不会改变子窗块的 text/text_hash，build.rs:63 的复用判定 existing.get(key)==text_hash 命中 → 旧向量复用，但其嵌入输入含旧 header 内容。触发条件：Composite 模式 + 修改大符号的 signature/docstring 但子窗行不变。错误行为：陈旧向量复用；应有行为：重新嵌入。上游防线（build.rs:40-47 的 model/dim/mode meta 比对）只防模式级变更，防不住 header 级变更。Raw 模式不受影响（输入即 text）。（src/vector/chunk.rs:322-333、src/vector/compose.rs:45-49、src/vector/build.rs:61-68）
3. 【P3·UTF-8 边界切片 panic（被 JoinSet 兜住成错误吞噬）】embed_one 非 2xx 分支用 &snippet[..snippet.len().min(200)] 按字节切片错误体；网关返回含中文/多字节字符的错误 JSON 且第 200 字节落在字符中间时直接 panic。该 panic 发生在 spawned 任务里，被 join_next 的 Err 分支吞成「嵌入任务中止: JoinError」，丢失原始 HTTP 状态、with_retryable 重试标记（embed.rs:168-176）与工人内 2s 重试机会（embed.rs:106-111）。上游防线不成立：外层只捕 JoinError 不恢复 panic 语义。触发条件：嵌入端点返回 ≥200 字节多字节错误体。（src/vector/embed.rs:166-177、src/vector/embed.rs:103-114）
4. 【P3·疑似·Composite 对非 ASCII 内容退化为纯 header】identifiers_of 只识别 ASCII [A-Za-z_][A-Za-z0-9_] 且 len≥4（compose.rs:14-39），中文文档/中文 docstring 的 fallback 与 leftover 块在 Composite 模式下嵌入输入几乎只剩面包屑（如「<fallback>」），语义信息全丢。本仓自己的大量中文 md 即如此。是否算缺陷取决于产品意图（默认模式即 Composite），验证方法：对 README.md 用 Composite 建索引后中文问题召回质量对比 Raw。（src/vector/compose.rs:14-39、src/vector/chunk.rs:368-369）
5. 【干净面声明】build_vector_index 编排本身审过且未发现缺陷：网络调用在事务外、GC+upsert+meta 同事务原子提交（store.rs:201-232）、embed 去重槽位回填 slot<unique.len() 无越界、响应 index 0-based 严格对齐校验（embed.rs:206-220）、mode 经 Debug 字符串 'Raw'/'Composite' 写 meta 且复用判定口径一致（build.rs:44-47 与 91）。（src/vector/build.rs:61-92、src/vector/store.rs:198-232、src/vector/embed.rs:72-146）
6. 【维B·残余物】descriptions 表（store.rs schema 71-75）全仓库无任何 INSERT/写入方，仅 remove_stale_on 事务里 DELETE（store.rs:134）；mod.rs 注释自认「描述层已移除、留 descriptions 表为兼容」。属已裁决移除功能的孤儿表——确定无写入方，疑似死（保留理由仅为'兼容'但无读取方）。另：VectorStore::upsert_chunk/remove_stale（非 _on 版本，store.rs:108-110/170-172）仅测试与潜在外部使用，pub API 不可判死。（src/vector/store.rs:71-75、src/vector/store.rs:134-135、src/vector/mod.rs:1-6）
