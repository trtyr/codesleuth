# 微观 · writeguard（writeguard）

> 置信度 high · 6 条发现 · 162263 tokens

writeguard 微观链路（writeguard::snapshot/walk/diff ← cli::run_task_inner 前后两次快照 + write_check 审计；外围 bootlock 引导锁与 graph.rs codegraph 启动、lib.rs 模块注册）整体实现扎实：symlink 防护、BTreeMap 确定性、SKIP_DIRS 豁免、错误路径留痕（write_check available:false）都正确。但发现 3 个真实缺陷：(1) P1——考前快照 `crate::writeguard::snapshot(&repo_abs).ok()` 把失败静默吞掉且不写 degraded 审计行，若考前快照失败，整个零写入自证机制无声消失，审计日志中连「不可用」痕迹都没有（考后失败有留痕，考前没有，属同链路不对称处理）；(2) P2——「零写入自证 ✓」stdout 结论存在被指纹弱化架空的窗口：>1MB 文件只取「size+首64KB」，文件中后段被改而大小不变时 diff 为空，但 stderr/审计仍输出确定性的「无变更 ✓」，自证声明强度与实际检测灵敏度不符（读失败按 0 字节计仅有 warn 日志，同样不进 write_check 行）；(3) P3——SKIP_DIRS 精确匹配目录名，大小写敏感且仅匹配这 8 个固定名，Windows 下 `.Codegraph`/`Dist` 等不会豁免（平台假设），另外构建产物常见目录如 `build`、`out`、`.next`、`vendor` 不在豁免表，非本进程写入会放大「不可归因变更」误报（如实上报语义下不瞒报，属灵敏度问题非完整性问题）。bug 密度最高文件：src/cli.rs（快照生命周期编排处）。死代码维度：链路内未发现确定死/疑似死——writeguard、bootlock 的全部 pub 符号（snapshot/diff/acquire/acquire_guard/BootLock 三态）均有生产调用或注册（lib.rs pub mod 全量导出），无注释掉的代码块、无调试残留。最值得先修：把考前快照失败从 `.ok()` 改为与考后一致的「留痕降级」（写 degraded 审计行 + stderr 警告），否则零写入自证这一安全防线可在无人知晓的情况下整条失效。

1. P1：考前快照失败被 .ok() 静默吞掉且无任何审计留痕——零写入自证防线可无声失效。cli.rs:287 `snapshot(&repo_abs).ok()`；对比同函数内 codegraph/向量层降级均写 degraded 审计行（cli.rs:306-309/362-365），考后快照失败也有 write_check available:false 留痕（cli.rs:463-473），唯独考前失败三不管。触发条件：仓库目录临时不可读/权限拒绝；错误行为：write_check 行整体缺失且无 degraded 痕迹，事后审计无法区分「无变更」与「防线未启动」；应有行为：写 degraded/write_check available:false 留痕。上游防线不成立：REPO_NOT_READABLE 错误码只在根目录不存在时提前返回（writeguard.rs:30-35），walk 内读目录/文件失败均转为 Err 直接穿透到 .ok() 被吞，无兜底。（src/cli.rs:287-287、src/cli.rs:303-311、src/cli.rs:463-473）
2. P2：大文件（>1MB）指纹弱化使「零写入自证：无变更 ✓」的确定性声明与实际灵敏度不符。writeguard.rs:81-93 对超限文件只哈希 size.to_le_bytes()+首 64KB；文件中后段被修改且大小不变（等长覆写）时 diff 为空，cli.rs:442-443 仍打印「无变更 ✓」，审计 write_check 的 unattributed_changes=0 呈现为强结论。触发条件：>1MB 文件等长中后段修改；错误行为：漏检且声称通过；应有行为：至少在 write_check 行标注指纹化文件数/灵敏度降级（当前仅 tracing warn，且读失败按 0 字节计的那条 warn 也不进审计）。上游防线不成立：注释自认「灵敏度降级必须可见」，但可见性只到 warn 日志，未进入自证结论通道。（src/writeguard.rs:77-97、src/cli.rs:442-444、src/writeguard.rs:88-91）
3. P3：SKIP_DIRS 精确大小写匹配是平台假设——Windows 不区分大小写的文件系统下 `.Codegraph`/`Target`/`Dist` 不会被豁免，进入 manifest 后工具自身写入会造成伪「不可归因变更」误报（不瞒报但冒领失败）；同时 `build`/`out`/`.next` 等常见构建目录不在表内，活仓库易产生持续误报。SKIP 表见 writeguard.rs:11-20，匹配逻辑 62-65 `SKIP_DIRS.contains(&name.as_str())`。（src/writeguard.rs:11-20、src/writeguard.rs:62-65）
4. 已审干净面：writeguard::walk 的 symlink 跳过（symlink_metadata 不跟随，防成环与出仓哈希，writeguard.rs:53-61）、strip_prefix 错误传播（68-73）、diff 的 Added/Modified/Removed 三分支与 BTreeMap 确定性排序（117-142）均正确，测试三方对质一致（symlink 测试 197-210、.codegraph 豁免测试 213-224）。（src/writeguard.rs:53-64、src/writeguard.rs:117-142、src/writeguard.rs:196-224）
5. 已审干净面：bootlock 引导锁链路——acquire 竞争轮询后 drop(file) 释放再返回 Lost（bootlock.rs:110-115，句柄即锁，无双重持有问题）；acquire_guard 三态映射正确（128-136）；graph.rs start_with_bin 在 Won 持锁期内做 init/force 后 drop 放锁，serve 阶段不持锁（graph.rs:75-97），与 writeguard 豁免面（.codesleuth/.codegraph）自洽。（src/bootlock.rs:101-121、src/bootlock.rs:128-136、src/tools/graph.rs:75-97）
6. 死代码维度：链路内零发现。lib.rs 全量导出 17 个模块（含 writeguard/bootlock，lib.rs:6-22）；writeguard 的 snapshot/diff 均有生产调用（cli.rs:287/425/427），无注释代码块、无调试残留、无孤儿簇；graph.rs 的 run_cli 仅被 start_with_bin 调用，链路闭合。（src/lib.rs:6-22、src/cli.rs:424-441、src/tools/graph.rs:25-67）
