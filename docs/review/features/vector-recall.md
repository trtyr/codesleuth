# 微观 · 向量召回引擎（vector-recall）

> 置信度 high · 6 条发现 · 308246 tokens

向量召回引擎链路（recall.rs → store/embed/chunk/compose/build → cli::setup_vector_layer → VectorSearchTool）整体设计干净：三段式查询、全行维度校验、commit_build 单事务、嵌入 index 对齐校验、内容去重回填都有正确实现且注释自觉。发现 1 个真实 P2 缺陷（embed.rs 错误响应按字节切片 200 可在多字节 UTF-8 边界 panic）；2 个 P3（HNSW 路径墓碑过滤后的 top-K 截断为「过滤后截断」而非「过滤前补采」，属文档承诺与实现次序不符的召回损失；recall.rs 模块注释 "<1000 走暴力" 与常量 100_000 漂移）。死代码维度：tombstone/tombstone_count/needs_compact/compact 四个公开 API 生产零调用（仅测试调用，文档自称"预留入口"）；descriptions 表只建只删从不写入。bug 密度最高文件：src/vector/embed.rs。最值得先修：embed.rs:173 的 UTF-8 边界 panic（改用 char_indices / floor_char_boundary 或 chars().take）。

1. P2 · UTF-8 边界 panic：embed_one 在非成功状态分支用 `&snippet[..snippet.len().min(200)]` 按字节切片错误体。serde_json::Value::to_string 不转义非 ASCII 中文/emoji（保持多字节 UTF-8），若第 200 字节落在多字节字符中间则直接 panic（byte index not a char boundary）。触发条件：嵌入网关返回含 ≥200 字节中文错误信息且边界劈开字符。错误行为：进程 panic 崩溃；应有行为：返回结构化 CsError。上游防线不成立：这是错误处理分支的最外层，异常路径本身即入口，无任何字符边界防护；且该分支在 embed() 的 2s 重试之后仍可能再次命中。修法：snippet.chars().take(N) 或 char_indices 定界。（src/vector/embed.rs:166-177）
2. P3 · HNSW 路径召回数不足风险（文档承诺 vs 实现次序）：注释宣称「k×3 超采 → 余弦复算 → 墓碑过滤取 top-K」，实现是先取 knbn=k*3 个候选再过滤墓碑再 truncate(k)——若候选中墓碑占比高，过滤后可能少于 k 条且不补采（OVERFETCH_FACTOR=3 恰为墓碑阈值 20% 的 15 倍冗余，正常时够，但这是数值巧合而非机制保证）。当前生产路径 tombstone 从不被调用（见死代码项），实际不触发，故降为 P3 疑似设计债而非活 bug；验证方法：墓碑化 >2/3 候选后断言结果数 <k。（src/vector/recall.rs:101-114、src/vector/recall.rs:17-18）
3. P3 · 注释漂移：recall.rs:4 模块文档写「<1000 向量走暴力」，而 MIN_HNSW_SIZE=100_000（recall.rs:20，与任务描述和测试 warm_start_brute_respects_alive 一致）。以常量为准，注释是旧阈值残留，误导维护者。（src/vector/recall.rs:1-22、src/vector/recall.rs:49-51）
4. 死代码（预留 API，文档已自认）：tombstone/tombstone_count/needs_compact/compact 四个 pub 方法在 141 个生产文件中零调用，仅 recall.rs 自身测试调用（recall.rs:237/248）；docs/contexts/向量检索/04-vector-recall.md:49 亦承认「仅测试调用方，预留入口」。引擎生命周期内 alive 恒等于全集，墓碑/压缩机制实际不生效——属于「写一半的功能」，与确认死代码分开列。（src/vector/recall.rs:69-97、src/cli.rs:593-662）
5. 残余物：descriptions 表只建（store.rs:71）只删（store.rs:134）从不插入——描述层 2026-10-04 被裁决移除，表为兼容保留（mod.rs:5 注释自述）。属确认的半死 schema 残余：GC 还为它执行永远 0 行的 DELETE。（src/vector/store.rs:70-75、src/vector/store.rs:134-135、src/vector/mod.rs:4-5）
6. 审过且干净的关键面（举证说明）：① store.rs remove_stale 键解析失败降 line_start=0 仅 warn 不误删（无 line_start=0 的行，DELETE 天然空操作）；② commit_build 把 GC+upsert+meta 包进单一 unchecked_transaction，build.rs 嵌入网络调用全部在事务外，无中间态窗口；③ build.rs stale_index 检查 model/dim/mode 三元组字符串精确比对，meta 不一致时全量重嵌不复用旧向量（防投毒）；④ embed.rs validate_index_alignment 拒绝非 0-based/乱序 index，去重回填 slots 映射核对无误；⑤ recall_by_vector 空库/alive 空/k=0 各边界（knbn=alive.len().max(1)、truncate）心算代入无 panic；⑥ plan_chunks 的行号钳制（max(1).min(len)、saturating_sub、空文件跳过 chunk.rs:418-419）覆盖越界；⑦ chunk_key 用 \u{1} 分隔符，file/symbol 现实不含该控制符；⑧ cli.rs setup_vector_layer 的降级路径（构建失败→复用、开库失败→无召回层、召回失败→空注入）均为 Ok 降级不致命，bootlock 构建段即放锁不跨 LLM 调用。（src/vector/store.rs:108-140、src/vector/store.rs:201-232、src/vector/build.rs:39-92）
