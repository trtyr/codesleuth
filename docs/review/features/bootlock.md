# 微观 · bootlock跨进程锁（bootlock）

> 置信度 high · 5 条发现 · 154273 tokens

bootlock 链路核心实现（acquire/acquire_guard/Drop unlock）基本正确：flock 语义、三态归一、超时判负（CS4016）、guard Drop 释放均与文档一致且有单测覆盖。真正的缺陷集中在「D020 语义变更后调用方未跟上」：Lost 被重新解释为「对手刚完成引导，产物已就绪」，但 flock 根本不保证这一点——对手可能在引导中途崩溃（内核放锁，waiter 拿到 Lost 却无产物）或在同一锁下多次进出。三个调用点对此的防御不一致：run_index_vector 有产物存在性回查（且回查失败后干脆无锁裸建，重新打开竞态窗口），setup_vector_layer 靠下游 open 失败降级兜底，而 graph.rs 的 OpponentFinished 路径完全不检查 `.codegraph` 是否存在/完整，直接 spawn serve——对手在 `index --force` 半途崩溃时会读到残缺库。共 4 条发现（P1×1、P2×2、P3×1），死代码维度基本干净。

1. P1 graph.rs OpponentFinished 路径无条件信任「对手刚完成」：对手在 init/index --force 半途崩溃（内核放锁）后，本进程拿到 Lost 跳过引导直接 spawn serve，会在缺失/残缺的 .codegraph 上启动结构工具。Won 分支有 `!root.join(".codegraph").exists()` 检查（graph.rs:86），Lost 分支一行防御都没有——复制粘贴改漏的典型形态。上游防线不成立：cli.rs:299 只对 CS4016（超时）判负，Lost 路径不产生错误；graph 工具后续空结果仅触发零增量熔断，掩盖而非暴露问题。（src/tools/graph.rs:83-97、src/tools/graph.rs:84-88、src/bootlock.rs:110-115）
2. P2 run_index_vector 的 OpponentFinished+产物缺失回退路径在**无锁**状态下执行 build_vector_index（cli.rs:200 注释自认「无锁增量补建」）：acquire 在 Lost 时已 drop(file) 放锁（bootlock.rs:113），此时第三个进程可立即 Won 同一把锁并行构建同一 index_dir——这正是 bootlock 要串行化的两层 check-then-act 之一被重新打开。上游防线不成立：注释声称「增量事务保护仍有效」，但事务保护只能保证单次一致性，不能防止两进程对同一索引目录并发写（commit_build/upsert 竞争），且该声称属清单外 vector/store.rs 内部，契约面未见互斥保证。（src/cli.rs:187-204、src/cli.rs:616-622）
3. P2 Lost≠「对手刚完成成功引导」这一隐含假设在 bootlock.rs:93 注释中成立性不足：flock 只表达「对方进程释放了锁」，对方可能崩溃（产物残缺）、也可能在锁上串行完成多次短引导后由第三方正在重新持有（Lost 返回后到调用方读产物之间窗口无保护）。run_index_vector 用 exists() 回查部分缓解，setup_vector_layer 靠 VectorStore::open 失败降级兜底（cli.rs:652-657，尚可），graph.rs 完全裸奔（见 P1）。触发条件：对手 crash 或紧接的第三进程竞争。应有行为：Lost 后校验产物完整性，不完整则按「锁已释放、可重新 Won」语义重试 acquire 而非直接复用。（src/bootlock.rs:93-95、src/bootlock.rs:5-10、src/cli.rs:651-658）
4. P3 acquire 把首次 try_lock 的硬错误（如 ENOLCK、EACCES、NFS 不支持 flock）一律包成 INDEX_LOCKED（CS4016，exit 5），消息「引导锁获取失败」误导用户以为是锁竞争；且该错误不带 hint、不可重试标记，语义上更接近 REPO_NOT_READABLE/INTERNAL。错误码段位复用导致诊断面失真，属错误分支语义误归类。上游防线不成立：cli.rs/errors.rs 均按段位直接映射 exit code，无细分。（src/bootlock.rs:87-89、src/bootlock.rs:116-118）
5. 干净面说明：bootlock.rs 主体（Won 首试/轮询/deadline 先检后睡/guard Drop unlock/句柄双保险）、acquire_guard 三态归一、errors.rs 的 INDEX_LOCKED 定义与 exit_code 段位映射（4000-4999→5）、setup_vector_layer 的 Won 分支 drop(vguard) 时机（构建后立即放锁、不跨召回/LLM，cli.rs:645）均经逐行读穿 + 三方对质（模块文档 D020 注释 vs 实现 vs 三调用点）确认一致；errors.rs 无死常量（4012/4013/5099 已在 P005 R6.2 清理，仅留注释），bootlock 公共符号 acquire/acquire_guard/BootLockOutcome 均有活跃调用点。（src/bootlock.rs:60-136、src/bootlock.rs:44-48、src/errors.rs:47-56）
