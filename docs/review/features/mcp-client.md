# 微观 · MCP客户端（mcp-client）

> 置信度 high · 10 条发现 · 574281 tokens

MCP 客户端链路（mcp.rs + graph.rs + cli.rs 装配段）整体实现是健壮的：spawn 错误分类（NotFound→4010+hint）、timeout_at 包裹单次 read_line、id 精确匹配丢弃通知、非法行跳过、bootlock 串行化引导、INDEX_LOCKED 不降级、Drop start_kill。发现 0 个 P0/P1；3 个 P2（响应行超长无上限可致无限循环；字符串 id 响应被静默丢弃致超时；Drop try_lock 失败时孤儿进程——崩溃/超时路径下成立）+ 4 个 P3（并发假设无防护——现全串行不触发；文档谎称设 CODEGRAPH_NO_DAEMON；run_cli 失败时 stdout 诊断丢失；embed_one 非 JSON 错误体吞掉 HTTP 状态码）。死代码维：list_tools 在仓库内零调用方（疑似死，属公开 API）；无孤儿簇、无成块注释代码。bug 密度最高文件：src/mcp.rs。最值得先修：mcp.rs:158 为读入行加长度上限（读端防御），以及 Drop 改为无条件 kill（写端确定性回收）。

1. 【P2·读端无行长上限】request 读循环对无 id 或 id 不匹配的行会继续读下一行，对非法 JSON 行 continue，但对「超长单行无换行」无任何上限：若 server 打印无换行的超长输出/巨型 JSON 响应，read_line 会无限累积内存直到 90s 超时。上游防线不成立的论证：write_line 只保证本端请求带换行，对 server 侧输出格式无任何约束（stderr 已 null，但 stdout 无约束）。触发条件：server 输出无换行超长行；错误行为：内存无界增长；应有行为：单行上限（如 1-10MB）即报 INDEX_BUILD_FAILED。（src/mcp.rs:152-190、docs/contexts/结构图与MCP/02-mcp-client.md:267-286）
2. 【P2·疑似】response_id 用 as_u64 只认数值 id；若 server 按 JSON-RPC 规范用字符串 id 回响应，该响应被永久丢弃，客户端挂到 90s 超时报 CS4014，无法区分「慢」与「id 类型不兼容」。防线：请求侧 id 恒为数值、规范 server 应回显同类型 id——防线基本成立，降疑似。验证法：用字符串 id 的 mock server 测 request。（src/mcp.rs:33-35、src/mcp.rs:179-187）
3. 【P2·疑似】Drop 用 try_lock 拿 child，锁被占时静默什么都不做：若锁被在途 request 持有或 guard 因 runtime 取消未释放，Drop 不 kill，server 成孤儿进程，且无日志无兑底。正常路径（cli.rs drop(agent)→drop(cg) 顺序）锁已空闲，防线大体成立，降疑似；但至少应记 warn。验证法：在 request 持 reader 锁的 await 点 cancel runtime 后观察 Drop。（src/mcp.rs:198-204、src/cli.rs:419-421）
4. 【P3·并发假设无防护】request 无单飞行闸：先写请求再循环抢 reader 锁；若未来任两处并发调用（锁在 read_line await 间释放），A 的响应可被 B 消费丢弃（id 不匹配被丢）→ A 永远等不到响应直到超时。当前全链路串行（cli.rs 装配后 Harness 单 agent 顺序执行、CodegraphEngine.call 无并发调用点），防线成立，非现行 bug，但接口未声明也未强制该约束。（src/mcp.rs:135-150、src/mcp.rs:152-170）
5. 【P3·文档 vs 代码不一致】graph.rs:5 文档注释声称「CODEGRAPH_NO_DAEMON=1 保证每会话独占进程」，但代码侧无任何 .env("CODEGRAPH_NO_DAEMON") 调用（spawn/run_cli 只设 CODEGRAPH_TELEMETRY=0 与 DO_NOT_TRACK=1）。若 codegraph serve 默认以 daemon 模式运行，Drop 的 start_kill 杀的是前台 wrapper 而非真正 server，独占回收承诺失效。三方对质（docs/contexts/00-overview.md:58 也承认此差异）但未修。（src/tools/graph.rs:3-5、src/tools/graph.rs:32-33、src/mcp.rs:72-73）
6. 【P3·诊断丢失】run_cli 失败分支只打印 stderr，stdout 被丢弃；stderr 为空时只能给通用 hint（锁竞争提示）。属诊断面可改进，非正确性缺陷。（src/tools/graph.rs:34-39、src/tools/graph.rs:52-66）
7. 【P3·错误语义】embed_one 先 resp.json() 再查 status：HTTP 4xx/5xx 若返回非 JSON body（网关 HTML 错误页），json() 先失败，报「embeddings 响应解析失败」且不带 HTTP 状态码、未标 retryable——瞬时故障兑底（2s 重试）仍会触发但外层看到的是误导性错误。（src/vector/embed.rs:162-177、src/vector/embed.rs:105-112）
8. 【干净面·已审】CodegraphEngine::call/symbol_args/五工具参数校验：symbol 空串/空白被 filter 拒（USER_INPUT）、explore query 同样校验、files 可选 filter 透传；graph.rs:114 args["projectPath"] 赋值在 symbol_args/FilesTool 恒构造对象的前提下安全（若外部传 args=null 会 panic——Value 索引赋值对 Null panic，但当前所有调用点均构造对象，属 pub API 误用风险非现行 bug）。（src/tools/graph.rs:113-118、src/tools/graph.rs:121-136、src/tools/graph.rs:222-234）
9. 【干净面·已审】cli.rs 装配链：INDEX_LOCKED 显式判负（锁超时不带残缺工具面）、非锁错误降级留痕、graph_symbols_nonempty 用 codegraph.db 判空防「空图工具烧 token」、run 结束 drop(agent) 再 drop(cg) 顺序回收；bootlock 三态语义（Won 执行引导后放锁 / OpponentFinished 跳过引导）与 graph.rs 消费一致。边界代入（cg=None、符号空、db 缺失）均有分支。未发现缺陷。（src/cli.rs:292-336、src/cli.rs:419-421、src/tools/graph.rs:83-96）
10. 【死代码】McpClient::list_tools 在仓库内零调用方（仅自身定义+测试+文档提及，CodegraphEngine 起动后从不调它），但属 pub API 且文档承诺三方法之一，判疑似死而非确定死。errors.rs:50,56 的 INDEX_STALE/INDEX_CORRUPT/5099 预留常量已由注释声明为预留，不算残余物。无成块注释代码、无孤儿簇、无调试残留。（src/mcp.rs:116-126、src/tools/graph.rs:97-105、docs/contexts/结构图与MCP/02-mcp-client.md:276-277）
