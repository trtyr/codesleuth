# 微观 · 审计日志（audit）

> 置信度 high · 7 条发现 · 264011 tokens

审计日志链路（audit.rs → harness 主循环 → cli 收尾 write_check → eval hardgate 消费）总体实现稳健：record 在 Mutex 锁内取号+写入保序，read_range 升序不重不漏，handoff/recall 的 seq 区间语义闭环正确。但找到 4 个真实正确性缺陷：(1) 最重要——CLI 失败路径完全跳过 write_check 零写入自证（agent.run 的 `?` 短路），安全自证恰在最可能出问题的会话中缺失；(2) 64MB 轮转后新文件 seq 从 1 重新起号且 `.old` 会被下次轮转静默覆盖，跨代 seq 重复使 evidence.audit_seq 引用歧义并丢史实；(3) Audit::create 不从已存在文件播种 seq，同 session_id 重入即产生重复 seq 破坏「不重」不变量；(4) record 取号在写入之前且 flush 失败仅 warn，写入失败会留下 seq 空洞（单调但「不漏」被侵蚀）。死代码维度基本干净，仅 audit.rs 尾部遗留一段被砍除功能的说明性注释块。

1. P2 · CLI 失败路径跳过零写入自证：run_task_inner 在 rt.block_on(agent.run(&task))? 处短路（cli.rs:419），任何 LLM/熔断/契约错误直接返回 Err，line 424 起的 writeguard diff + append_line(write_check) 全部不执行。guard_before 快照已付出成本（cli.rs:287）却永不比对。错误行为：失败会话（恰是最需要自证的会话）审计无 write_check 行、stderr 无自证摘要，不可归因变更无人知晓；应有行为：失败路径同样落 write_check（哪怕 available:false）。上游防线不成立：harness 内部留痕不覆盖 CLI 层的快照 diff，此为唯一防线。（src/cli.rs:419-475、src/cli.rs:287-287）
2. P2 · 64MB 轮转后 seq 跨代重复且 .old 静默覆盖：轮转把旧文件改名 .old，新 Audit 从 AtomicU64=0 重新起号（audit.rs:101），新代第一批 record 的 seq 1..N 与 .old 内 seq 1..N 完全同号；read_range 只读当前 path（audit.rs:116），旧代对 recall 不可见。且下次轮转 rename 直接覆盖既有 .old（audit.rs:84），更早一代无提示丢失。错误行为：报告 evidence.audit_seq 跨代歧义、事实账本丢史实；应有行为：新代从全局偏移续号或至少 seq 编入代际。上游防线不成立：注释（audit.rs:77-78）仅自认「recall 读不到」，未覆盖 seq 重复歧义与 .old 覆盖丢数据两点。（src/audit.rs:76-102、src/audit.rs:76-78）
3. P3 · Audit::create 不播种 seq：create 以 create(true).append(true) 打开已存在文件时 seq 仍从 0 起算（audit.rs:101），record 将写出与既有行重复的 seq 1..N，「按 seq 单调不重」不变量破。触发条件：session_id 碰撞或外部以同 id 复建 Audit（new_session_id 纳秒+pid 使概率极低，故降 P3）。上游防线论证：轮转分支只在 >64MB 时清场，其余路径无任何去重/播种保护。（src/audit.rs:93-102、src/audit.rs:76-76）
4. P3 · record 取号在写入前、flush 失败仅 warn：fetch_add（audit.rs:147）先于 writeln/flush（audit.rs:151-161），写失败时 seq 号已消耗形成空洞（recall「不重不漏」的『不漏』被侵蚀），flush 失败只 tracing::warn 不返回错误，违反自身「审计丢行=关键失败不留痕」的注释意图（audit.rs:158-159）。上游防线：harness 各 record 调用点用 ? 传播 writeln 错误，但 flush 失败分支无任何防线。（src/audit.rs:144-161）
5. P3 · read_range 把无/非法 seq 的行当作 seq 0：v.get("seq").as_u64().unwrap_or(0)（audit.rs:126），半行/损坏行会被纳入 from=0 的 recall 结果冒充 seq 0 行。触发条件：外部截断或手工编辑审计文件。轻微（自产行必有 seq）。（src/audit.rs:115-133、src/harness.rs:344-352）
6. 已核对干净面：record 的锁内取号+写入保 JSONL 单调（audit.rs:144-150，含注释论证）；payload 键冲突顶层胜出两处一致（audit.rs:31-39 vs 138-150）；handoff 硬编码 from=1 与 seq 从 1 起号匹配（harness.rs:124-126，测试 context.rs:125-129 对质）；recall from/to 缺省退化安全；compaction_begin/compaction 仅真实驱逐时留痕；eval 侧 stderr 正则 AUDIT_LINE 与 cli 输出「# 审计: 」匹配一致（run_eval.py:30 vs cli.rs:507-513）；writeguard snapshot/diff 的 symlink 跳过与 >1MB 指纹逻辑正确（writeguard.rs:53-97）。（src/audit.rs:136-150、src/harness.rs:124-142、src/harness.rs:338-361）
