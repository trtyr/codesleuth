# 微观 · 配置加载链（config-loading）

> 置信度 high · 6 条发现 · 296551 tokens

配置加载链主体（load → load_layered → merge_file → apply_profile → merge_cli → resolve_api_key）实现正确：分层覆盖顺序、档位逐层收集（profiles.extend 项目压全局）、CLI 旗标最后覆写、未知档位列名报错、空白密钥视为未配置，均有测试对质且实现与文档一致。发现 2 个真实缺陷：(1) P2——`config get`（无键全量打印）经 to_file_view 输出时 context 段硬编码 FileContext::default()，生效的 context.model_context_tokens / compact_at_percent 两个合法键在全量视图中被静默丢弃，与键表驱动的 resolved_get 语义不一致；(2) P3——llm.rs 重试退避注释声称 500ms/1s/2s/4s，实际代码 `500 << attempt` 产出 1s/2s/4s/8s，注释与实现单位差一。另有若干 P3 观察项。死代码维度基本干净，仅测试名残余物（env 层已删但测试名仍叫 precedence_cli_beats_env_beats_...）。bug 密度最高文件：src/config.rs（to_file_view）。最值得先修：to_file_view 补齐 context 段。

1. P2 bug：config get 全量视图丢失 context 配置。to_file_view 把 context 段硬编码为 FileContext::default()（config.rs:508），而 context.model_context_tokens 与 compact_at_percent 是键表中合法可 set/get 的键（config.rs:368-385）。触发条件：用户设置了 context.* 后运行 `codesleuth config get`（无键）——输出 TOML 中 [context] 段缺席/为空，错误行为 vs 应有行为：应显示生效值，实际静默丢失。上游防线不成立：resolved_get 单键读取路径正确，但全量路径（cli.rs:730 to_file_view）绕过键表直接构造，两路不一致；用户看全量输出会误以为 context 未生效。（src/config.rs:500-524、src/config.rs:368-385、src/cli.rs:724-735）
2. P3 bug：重试退避注释与实现不一致（单位差一）。llm.rs:247 注释称『500ms / 1s / 2s / 4s（封顶）』，实现为 `500u64 << attempt.min(4)`，attempt 从 1 起算，首次退避即 1000ms，序列实为 1s/2s/4s/8s。触发条件：任何触发重试的 LLM 调用（max_retries=2，见 cli.rs:274）。行为影响小（多等 0.5s），但注释承诺与实际不符，属复制粘贴/差一类的文档性缺陷。（src/llm.rs:243-249、src/cli.rs:271-276）
3. 干净段论证：分层合并主链（load_layered + merge_file + apply_profile + merge_cli）经三方对质（模块文档 config.rs:1-3 优先级声明 vs 实现 vs 测试 precedence_*/profile_* 系列）逐字段核对，覆盖顺序正确；profiles 逐层 extend 保证项目同名档位压全局（测试 project_profile_overrides_global_same_name 证实）；--profile 未知名报错并列出可用档位；merge_cli 仅 base_url/model 两旗标最后覆写，与文档『旗标永远最后覆写者』一致。空/单层/双缺文件边界由 missing_files_fall_back_to_defaults 覆盖。（src/config.rs:206-223、src/config.rs:227-259、src/config.rs:623-643）
4. 干净段论证：resolve_api_key 只认配置文件直配且空白串视为未配置（trim 判空），resolve_embed_endpoint 的 [vector] 缺省跟随 [llm] 语义在 cli.rs 两处调用（run_index_vector、setup_vector_layer）与键表 get 闭包（vector.base_url/api_key 的 unwrap_or_else 回退）三处口径一致。（src/config.rs:526-539、src/config.rs:645-652、src/cli.rs:577-589）
5. P3 观察：`codesleuth config set --profile xxx` 时 profile 旗标被静默忽略（run 分支只把 profile 传给 Get 分支，Set 走 config_set 不接收 profile）。无功能破坏但属接口面不对称，值得在 CLI 帮助文本或拒绝路径澄清。（src/cli.rs:125-126、src/cli.rs:553-562）
6. 死代码维残余物：测试名 precedence_cli_beats_env_beats_project_beats_global 仍含 'env'，但环境变量层已于 2026-10-05 整体移除（config.rs:3）——名称性残余物，建议改名以免误导。未发现确定死代码：project_config_path_legacy 由 load:200-202 回退调用；keys_hint/find_key 由 apply_set/resolved_get 共用；to_file_view 由 config_get 使用（虽有 P2 缺陷但非死）。（src/config.rs:622-643）
